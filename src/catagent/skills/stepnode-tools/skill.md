# StepNode tools

This skill explains the usage of tools in StepNode subagent. These tools are organized in different collections. Call `get_tool_collection_infos` to get all the available tool collections and call `load_tool_collection` to load a specific collection.

NOTE: The tools in "structure_building_tools" collection and `bind_to_surface` in "reaction_system_tools" will use general coordination number (GCN) to classify all the atoms in the topmost layer. When building structures, these tools enumerate these classes (each class represent a different local chemical environment), randomly pick an atom from a class and attach adsorbate to it. This make adsorbate close to the top site, but these tools will disturb the positions of adsorbate to prevent the structure from falling in to local minimum.

## "structure_building_tools" collection.
This collection contains tools which can build IS and FS, adsorption structure, and initial NEB path. Do not bother yourself to check the structures generated by these tools, they are already reasonable and can be directly use in DFT or MLFF relaxation.
- `build_ini_fin_structures_on_surface`: Given IS and FS molecules, automatically match their atomic indices, then attach them on a surface. 
- `build_nebpath_on_surface`: Given IS and FS, build neb path. This tool will handle some special cases, for example, it will adjust the structure if molecule dissociates in vacuum. 
- `build_adsorption_configs_on_surface`: Attach a SINGLE adsorbate on the surface.


## "reaction_system_tools" collection 

This collection have tools which can generate, edit and visualize the reaction network. For a total reaction, such as CH4 + CO2 <-> 2* CO + 2* H2, there are infinite elementary reactions in theory, because we can generate infinite intermediates by combing atoms and atomic groups. Considering the computation cost, we need to set constraints when generate a reaction network. There are also multiple isomers for a chemical formula, for example, CHOH have the same formula as CH2O, you cannot distinguish reactions "HCO + H <-> HCOH" and "HCO + H <-> H2CO" from the chemical formulas. To distinguish them, we provide visualization tool to render the reaction into `.png`, let the user to select the reactions and intermediates they need. Some tools in this collection need Human-In-The-Loop (HITL), you should call `pause_to_ask` to ask the user for args before you call them.


- `create_reaction_system`: Call this tool firstly, you should create a reaction system before generating and editing reaction network.
- `generate_elementary_steps`(HITL): Generate intermediate fragments and elementary reactions satisfying certain constraints. 
- `render`: Render the reactions and intermediates into png pictures. The user should inspect these pictures to determine which reactions and intermediates will be deleted.
- `delete_species`(HITL): Delete intermediates from the system. 
- `delete_reactions`(HITL): Delete reactions from the system.
- `merge_reactions`(HITL): Merge some reactions. `generate_elementary_steps` only consider single-bond forming or breaking, reactions such as "NHOH + H <-> NH + H2O" will be split into two or three reactions, for example, "NHOH <-> NH + OH", "OH+H<->H2O". We need call `merge_reactions` to let the user determine which reactions should be merged.
- `dump`: Dump the reaction system object to a pkl file, so that it can be used in another run.
- `load_from_file`: Load a reaction system object from pkl file.
- `has_reaction_system`: Check if a reaction sytem exists.
- `delete_reaction_system`: To save memory, we should delete the object when edit task is done.
- `bind_to_surface`: Given a surface structure, bind all the initial and final states to the surface. For complex surface, such as Fe(110), there will be many configurations, user should select which will be kept to limit the computation cost. The atomic indices in IS and FS are matched, you can safely interpolate use these structures to make NEB pathes.

### General workflow to generate a reaction network
Take reaction CH4 + CO2 <-> 2* CO + 2* H2 as an example.
1. Generate all the reactants and products structures, using `*.xyz` format.
    ```bash
    python << 'EOF'
    from ase.io import write
    from ase.build import molecule
    for mol in ["CH4", "CO2", "H2", "CO"]:
      write(f"{mol}.xyz", molecule(mol))
    EOF
    ```
    Also generate the surface we want to study. You can call `build_slab.py` in `structure-building` skill to do this.

2. Call `create_reaction_system` to generate a reaction system. 
3. Call `pause_to_ask` to let the user specify the args of  `generate_elementary_steps`, then call `generate_elementary_steps` to generate intermediates and elementary steps. 
4. Call `render` to render reactions and intermediates into pngs, then Call `pause_to_ask` to notify the user inspect these pictures, ask if they accept the current network. If not, go to step 3.
5. After user confirm the network. Call `pause_to_ask` to ask the user, which reactions they want to merge, which reactions they want to delete and which species they want to delete. Note that, `delete_species` and `delete_reactions` will automatically clean the *isolated* reactions and species (some reactions may become isolated nodes in the network after some others reactions or species are deleted). Let the user specify the reactions or species indices, then call `merge_reactions`, `delete_species` and `delete_reactions`. Because the reactions and species indices will change after deletion, you should call `render` again after you edit the network, to let the user know the correct indices after edit.
6. When network edit complete, you can call `dump` to dump the reaction system object into a pkl file. Then call `bind_to_surface` to attach IS and FS of each elementary step to surface. At last, you should call `delete_reaction_system` to delete the object from memory.
