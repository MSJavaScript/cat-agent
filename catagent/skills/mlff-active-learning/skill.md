# Obtain high-precision MLFF through finetuning and active learning 

Finetuing is a fast method to get accurate MLFF from a pre-trained model. This skill explains how to iteratively finetune a MLFF, especially the application on catalysis computation.  The basic idea is a sampling & DFT labelling → finetuning MLFF → sampling & DFT labelling loop.

## Workflow in catalysis computation

### 1. Build the initial training dataset

Build the initial and final states (IS and FS) for each elementary reaction and interpolate between IS and FS to get a rough NEB path (only used to sample structures, as IS and FS are not relaxed yet). Use `scripts/rattle_configs.py` to perturb the atomic postions:
```bash
python3 rattle_configs.py -i POSCAR -o POSCAR_rattle.extxyz -n 4  
``` 
This enlarges the configuration space covered by training dataset. We can use a script like below to perturb structures and generate VASP inputs for single point calculations in batch:

```bash
i=0
source_dir=$1
find "$source_dir" -type f -name "*.extxyz" -print0 |
while IFS= read -r -d '' file; do
    # Suppose .extxyz file contains a NEB path, two end points are IS and FS
    # Rattle this NEB path to enlarge configuration space
    python3 rattle_configs.py -i ${file} -o path_rattle.extxyz -n 4 

    # 5 structures for each image
    cat path_rattle.extxyz ${file} > total.extxyz

    # Extract all the structures to POSCAR format:
    python3 << 'EOF'
    from import ase.io import read, write
    configs = read('total.extxyz', index=':')
    for i in range(len(configs)):
        write(f'POSCAR_{i}', configs[i])
    EOF

    # Generate KPOINTS and POTCAR for this batch of POSCAR_* 
    # ...

    # Suppose INCAR is almost the same, we only need to
    # modify MAGMOM or LDAUU tags, which depends on POSCAR
    cp INCAR.tmp INCAR
    # Modify certain tags ...

    for poscar in POSCAR_*
    do
      mkdir sp_${i}
      let i=i+1
      mv ${poscar} sp_${i}/POSCAR
      cp INCAR KPOINTS POTCAR sp_${i}
    done

    rm -f INCAR KPOINTS POTCAR 
    rm -f path_rattle.extxyz total.extxyz
done
```

Then you can submit a batch job including all the `sp_*` dirs and get the initial training dataset by `scripts/gather_dft_results.py`
```bash
python3 gather_dft_results.py -o results.extxyz
```

### 2. Finetune MLFF

Take DPA4 as an example. Firstly, convert the collected data to `hdf5` format:
```bash
python3 extxyz_to_hdf5.py results.extxyz dataset1.hdf5
```
Then prepare the `input.json` for DPA4 finetuing.
```bash
python3 get_input_json.py \
  --training_data_path "dataset1.hdf5" \
  --training_natoms <Set appropriate value here>
```
Run DPA4 finetuning using the following commands
```bash
dp --pt train input.json --finetune ${model} > train_log 2>&1
dp --pt freeze -c model.ckpt.pt -o frozen
dp --pt test -m frozen.pt2 -s dataset1.hdf5 -d pred_val > infer_val_log 2>&1
```

### 3. Run structure relaxation and NEB
Now we get an initial force field, we can use it to run structure relaxation and NEB. 

Use `scripts/run_ase_neb_with_dpa.py` to run structure relaxation or NEB with DPA force field. It generates a `*.json` file containing the state of this run (if this run converged and error message) and the final relaxed structures or NEB path. Below are the files that will be generated by `opt` and `neb` tasks. "save_name" is set by `--save_name` option.

|task|final structures|json | traj|
|---|---|---|---|
| opt| POSCAR_<save_name>.result | <save_name>_opt_state.json|<save_name>_opt.traj|
|neb| <save_name>.result.extxyz | <save_name>_neb_state.json |<save_name>_neb.traj|

```bash
# run structure relaxation
python3 run_ase_neb_with_dpa.py \
  --pt fronzen.pt2 \
  --save_name opt1 \
  opt --infile POSCAR

# Add constraint on the bond length between atom 10 and 12. 
# This option is useful when you want to prevent the decomposition of adsorbates or the auto-binding between fragments. However, this option will cause error when the structure is unreasonable, especially when the bond length between two specific atoms is fixed in a transition state like structure. 
# Fix bond length are usually safe for IS and FS relaxation.
python3 run_ase_neb_with_dpa.py \
  --pt fronzen.pt2 \
  --save_name opt2 \
  opt --infile POSCAR --bond "10,12"

# Set the atomic indices of adsorbate, 
# check if the adsorbate dissociated or combined 
python3 run_ase_neb_with_dpa.py \
  --pt fronzen.pt2 \
  --save_name opt3 \
  opt --infile POSCAR --ads_indices "10,11,12,13"

# Run NEB, providing initial and final states
python3 run_ase_neb_with_dpa.py \
  --pt fronzen.pt2 \
  --save_name neb1 \
  neb --neb_ini POSCAR_ini --neb_fin POSCAR_fin

# Run NEB, providing an initial NEB path
python3 run_ase_neb_with_dpa.py \
  --pt fronzen.pt2 \
  --save_name neb2 \
  neb --neb_path neb_path.extxyz
```

To run relaxation and NEB in batch, you should copy `run_ase_neb_with_dpa.py` into job dir and write `run.sh` as shown below.
```bash
# Suppose there are POSCAR_*_ini and POSCAR_*_fin files in ini_fin dir.
# These files are the initial and final states of NEB path (have not been optimized)

for poscar_ini in ini_fin/POSCAR_*_ini
do
  name=`echo ${poscar_ini} | cut -d_ -f2`
  poscar_fin=POSCAR_${name}_fin

  # firstly, run the structure relaxations of IS and FS
  python3 run_ase_neb_with_dpa.py \
    --pt fronzen.pt2 \
    --save_name ${name}_ini \
    opt --infile ${poscar_ini}
  
  python3 run_ase_neb_with_dpa.py \
    --pt fronzen.pt2 \
    --save_name ${name}_fin \
    opt --infile ${poscar_fin}
  
  # We can skip neb, if IS and FS relaxation fail.
  grep success ${name}_ini_opt_state.json
  if [ $? -ne 0 ]
  then
    echo Relax IS fail. Continue.
    continue
  fi
  # do the same for FS

  # Then run NEB.
  python3 run_ase_neb_with_dpa.py \
    --pt fronzen.pt2 \
    --save_name ${name} \
    neb --neb_ini POSCAR_${name}_ini.result \
    --neb_fin POSCAR_${name}_fin.result
done

mkdir json traj poscar
mv *.json json
mv *.traj traj
mv POSCAR* poscar
```


### 4. Check the trajectory and extract structures
Running NEB and structure relaxation with MLFF sometimes fails, because potential energy surface (PES) maybe not well described. If the relaxation trajectory is too long, we consider it to be problematic and extract structures from it.  Use `scripts/check_traj.py` to do this.

```bash
# Extract structures from structures relaxation trajectory
python3 check_traj.py --traj opt.traj -o opt_out.extxyz -n 5 

# Extract structures from NEB trajectory, two end points are ignored because they are IS and FS and keep fixed during the relaxation.
python3 check_traj.py --traj opt.traj -o neb_out.extxyz  --neb -n 5
```
use `--nstep_thres` to set the threshold of reasonable steps.

You can use a bash script like the following to extract structures and prepare VASP inputs in batch.

```bash
for traj in *_ini_opt.traj
do
  name=${traj%_ini_opt.traj}

  python3 check_traj.py \
    --traj ${traj} \
    --save_name=${name}_ini_ex -n 3

  python3 check_traj.py \
    --traj ${name}_fin_opt.traj \
    --save_name=${name}_fin_ex -n 3
  
  python3 check_traj.py \
    --traj ${name}_neb.traj \
    --save_name=${name}_neb_ex -n 3
  
  cat ${name}_ini_ex.extxyz ${name}_fin_ex.extxyz ${name}_neb_ex.extxyz > total_${name}.extxyz

  # Generate inputs for single point vasp calculation
  # Similar with "Build the initial training dataset"
  # ...
done
```
### 5. Repeat 2,3,4, until we cannot extract structures from trajectories

When DFT job is done, we get another training dataset, say "dataset2.hdf5". Then we finetune a new MLFF with "dataset1.hdf5" and "dataset2.hdf5".  Always finetune from scratch. This guarantees that both datasets are used in the same number of epoches during training. 

We repeat the steps 2,3 and 4, until all the structure relaxations and NEBs converge within a reasonable range of steps, that is, `check_traj.py` cannot extract structures from the trajectories anymore.


## Workflow for general systems
If you only want to run MD or calculate the state of equation (EOS) of a system, the workflow is much simpler.

### 1. Build the initial training dataset
Firstly rattle the cell and atomic positions of initial structure:
```bash
python3 rattle_configs.py -i POSCAR_Si -o rattle_Si.extxyz -n 4 -c 
```
Tips: For bulk system, each structure should contains sufficient number of atoms (e.g. > 40), use ase `.repeat()` to enlarge the cell.
```bash
python3 << 'EOF'
from ase.io import read, write
atoms = read("POSCAR_in")
atoms.repeat((a1, a2, a3))
write("POSCAR.out")
EOF
```
If there are multiple elements, use sort_elements.py to sort them, because `.repeat()` does not adjust the order automatically.
```bash
python3 sort_elements.py -i POSCAR_out -o POSCAR_out_sorted
```


For each of the rattled structure, run NPT md to sample the system. 
```bash
# Extract the rattled structures to POSCARs
python3 << 'EOF'
from ase.io import read, write
atoms_list = read("rattle_Si.extxyz", index=":")
for i in range(len(atoms_list)):
    write(f"POSCAR_{i}", atoms_list[i])
EOF
```
Because we don't have a finetune MLFF yet, we run MD with the pre-trained model. `run.sh` can be the following:
```bash
model=<model_path>/<model_name>
dp --pt freeze -c ${model} -o frozen
# suppose we get a frozen.pt2
for poscar in POSCAR_*
do
    idx=${poscar#POSCAR_}
    for t in 500 1000 # Temperature in K
    do
        for p in 0.001 0.02 # Pressure in GPa
        do
            python3 run_ase_npt_md_with_dpa.py \
            --pt frozen.pt2 \
            --save_name MD_${idx}_${p}_${t} \
            --infile POSCAR_${idx} \
            md -t ${t} -p ${p} \
            --dt 2.0 --nsteps 2000 --log_interval 20 
        done
    done
done
```
We loop through all the POSCARs and run MD under different temperature and pressures. Here `scripts/run_ase_npt_md_with_dpa.py` is a script for NPT MD, you should copy it to the job dir.

### 2. Extract structures and label them by DFT
We then extract structures from the `*.traj` files. 
```bash
for traj in *.traj
do
    python3 check_traj.py --traj ${traj} \
    -o extract_md.extxyz --nstep_thres 1 -n 20
    # Prepare VASP inputs ...
done
```
Here is a little trick, you can regard this `.traj` file as generated by structural relaxation, use a small `--nstep_thres` to get structures from the it.

### 3. Finetuning
We collect the DFT results, convert it to `hdf5` format and finetune the MLFF.
```bash
dp --pt train input.json --finetune ${model} > train_log 2>&1
dp --pt freeze -c model.ckpt.pt -o frozen
dp --pt test -m frozen.pt2 -s structs.hdf5 -d pred_val > infer_val_log 2>&1
```
We get a finetuned MLFF now, the RMSE of energy and force can be get by 
```bash
tail -n 15 infer_val_log
```
If the precision does not reach the target, we then sample structures by MD using the **finetuned MLFF** and label them by DFT. Repeat these steps to improve the MLFF iteratively, until we reaches the target precision.

## Finetune the force field for different systems respectively
To ensure the accuracy of finetuning, we perform the active learning separately for different systems. The criterias to dividing different systems are element compositions or chemical properties of the system. For example, Fe(110), Fe(111) and Fe(211) are taken as the same systems, while Cu(111) and Pt(111) are different systems. For alloy surfaces, for example, NiCu, NiCo and NiPt, three surfaces based on Ni, they only underwent elemental substitution therefore can be regarded as the same system.
 

## Practical suggestions for file and state management

Every step will generate a lot of files. To keep the file system clean, Orchestrator should make a series of dirs for each step (if there are multi systems, make separate workdirs for each of them.), e.g. 
```
iter0_init_sampling   iter0_finetune    iter0_mlff_neb
iter1_DFT_sampling    iter1_finetune    iter1_mlff_neb ...
```
The StepNode should make sure to work in a subdir which corresponding the current step. 

There are many elementary reactions in a study, give them a descriptive name such as `<reaction_name>_<facet>_<index>`. To avoid omissions, StepNode should maintain a `report.md` during execution. For example:
```md
# report: iter0_mlff_neb
Run NEB and structure relaxation with MLFF.

## Results
25 Calculations in total.

Passed reactions (20)
> "CH4-CH3+H_Rh111_0", "CH2-CH+H_Rh111_0", "..."

Failed reactions (5)
> "CO2-CO+O_Pt111_0", "..."
```
Orchestrator will read `report.md` and log the status of this step in `state.md`. For example:
```md
# State logging
(Description of this project)
## iter0_init_sampling
Build the initial training dataset of system xxx.

Status: Done

## iter0
...

## iter0_mlff_neb
Run structure relaxation and NEB with MLFF
Passed reactions (20)
> "CH4-CH3+H_Rh111_0", "CH2-CH+H_Rh111_0", "..."

Failed reactions (5)
> "CO2-CO+O_Pt111_0", "..."
```
With these records, we can identify which reaction failed when calculated using MLFF, and subsequent sampling and calculations will only be conducted on the failed reactions. After all tasks are completed, we can also collect results based on these records.

The same strategy also applies to general cases. Orchestrator should make a series of workdirs
```
step0_init_MD  step1_DFT  step2_finetune  step3_MD ...
```
A `state.md` file should be maintained in top level dir to log the working state.

## Scripts

Below are the related scripts in `scripts` dir. Run these scripts without parameters or with `-h` to get the helps.
| Name | Purpose|
| ---- | ---- |
|check_traj.py| Check the trajectory and extract structures from it if it is problematic. |
|gather_dft_results.py| Collect the calculated structures into an extxyz file|
|rattle_configs.py|Perturb the structures to enlarge the configuration space |
|run_ase_neb_with_dpa.py| Run structure relaxation (cell is fixed) and NEB with DPA force field|
|run_ase_npt_md_with_dpa.py|Run structure relaxation (cell can be relaxed ) and NPT MD with DPA MLFF.|
|sort_elements.py| Sort the elements in a POSCAR.|
