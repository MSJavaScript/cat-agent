# Guides for File and State Management

This skill explains the guidelines of file management and how to use `.md` file to log the status of job. The layout of current agent has 3 parts: Orchestrator, workflow router (Router) and step execution node (StepNode). They work together to complete the file and state management.

- Orchestrator: Create workdir and prepare required files for a plan step. Log the status of step in `state.md` (in top workdir).
- Router: Programmatically write a `readme.md` in the workdir of each step to remind StepNode of the task content.
- StepNode: Maintain a `report.md` during execution. 

Before StepNode starts to work, Orchestrator should copy all necessary files, e.g. output artifacts from previous steps, to the sub-workdir or create soft links. When a step is done, StepNode should write a summary section in `report.md` to summary this run and log error messages (if any).

Keep all the `.md` files concise and formatted, make sure they are understandable to human and other agents.

## Example : Iteratively finetune the MLFF
The structure of work dir may be:
```
├── state.md
├── step0_init_MD
│    ├── readme.md
|    ├── report.md
|    ├── POSCAR_*
|    ├── run.sh
|    ├── run_ase_npt_md_with_dpa.py
|    ├── job_description.json
|    └── rattle_Si.extxyz 
|
├── step1_DFT
|    ├── readme.md 
|    ├── report.md
|    ├── run.sh
|    ├── job_description.json
|    └── sp_0, sp_1, ...
|
├── ...
```

Take the `step0_init_MD` dir as an example. `readme.md` always has 5 sections:
```md
# readme: step0_init_MD
## Content
Get initial training dataset by running MD with pre-trained model.
## Solution
Run MD on rattled structures under different pressure and temperatures.
## Related skills
...
## Required Artifacts
...
## Output Artifacts
...
```

The format of `report.md` is more flexible, it may log the calculation parameters, current working state and all the other informations of the current step. For example, the `report.md` below records the analysis result of a data file and the status of job submission (use `edit_file` tool to write texts with timestamp):
```md
# report: step0_init_MD

## Calculation parameters
T(K): 100 500
p(GPa): 0.1 0.05
The number of MD steps: 2000

## Status
[2025-09-08 09:11:39] All the inputs are generated. This batch contains 100 jobs and has been submitted to remote.
[2025-09-08 09:11:40] Waitting for the results ...

## Working Experience
The format of `binding_info.json` generated by tool xxx is ...
It contains ...
### How to use
...
```
If the current step is done. `report.md` should have a summary section


```md
# report: step0_init_MD
... (omit the content above)

## Summary 
[2025-09-08 10:00:43] This step completed. 10 traj files are collected.
Status: success (or error)
(error messages also go here.)
### Files and dirs list
(List important files and dirs by a table, especially when there are multiple jobs in different dirs)
|Path|description |
|---|---|
|vasp_01~vasp_09|a series of vasp jobs|
|./dpa4/model.pth|dpa4 checkpoint file|
```
Router will sent the result to Orchestrator. Orchestrator can read `report.md` and log the status of the step in `state.md`:

```md
# State Logging
This file contains the state logging of xxx. (We can add a short description of the project here.)

## step0_init_MD
Run a series of MD under different T and P. 

Calculation parameters:
- temperatures (K): [100, 500]
- pressure (Gpa): [0.1, 0.05]
- nsteps: 2000

Status: success (or error)

## step1

Extract structures from the traj files and label them by DFT.

Extracted 5 structures from each traj, 100 structures are collected in total.
...
```
The format of `state.md` is also flexible, but try to keep a consistent and formatted style for similar steps.
